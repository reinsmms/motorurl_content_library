					<div class="content"><p>Learn about programming considerations for the Single Document Interface in Excel.</p>
<div class="heading-wrapper" data-heading-level="h2"><a class="anchor-link docon docon-link" href="#comparing-single-and-multiple-document-interfaces-in-excel-2010-and-excel-2013" aria-label="Section titled: Comparing Single and Multiple Document Interfaces in Excel 2010 and Excel 2013"></a><h2 id="comparing-single-and-multiple-document-interfaces-in-excel-2010-and-excel-2013" class="heading-anchor">Comparing Single and Multiple Document Interfaces in Excel 2010 and Excel 2013</h2></div>
<p>A new feature in Excel 2013 is the single document interface (SDI). SDI is a method of organizing graphical user interface (UI) applications into individual windows that the operating system window manager handles separately. In Excel 2013, each Excel window can contain only one workbook, and each has its own ribbon UI (see Figure 1). By default when you open a new workbook, it will be displayed in another Excel window, even though it is the same Excel instance.</p>
<p><strong>Figure 1. Single Document Interface in Excel 2013</strong></p>
<p><img src="../../images/odc_xl15_ta_programmingthesdiinexcel2013_01.jpg" alt="Single Document Interface in Excel 2013" data-linktype="relative-path"></p>
<p>This contrasts with a multiple document interface (MDI), in which a single parent window is used to contain multiple nested child windows, with only the parent window having a menu or tool bar. In Excel 2010, each workbook in a single instance of Excel utilizes a common ribbon UI (see Figure 2).</p>
<p><strong>Figure 2. Multiple Document Interface in Excel 2010</strong></p>
<p><img src="../../images/odc_xl15_ta_programmingthesdiinexcel2013_02.jpg" alt="Multiple Document Interface in Excel 2010" data-linktype="relative-path"></p>
<p>Excel 2010 uses the MDI, which means that there is a single application-level window holding all the workbooks that are open in a particular instance of Excel. The windows of the workbook can be arranged inside the Excel app window, all sharing the same Ribbon UI. SDI in Excel means that each workbook will have its own top level app window, and has its own corresponding Ribbon UI.</p>
<div class="alert is-info">
<p class="alert-title"><span class="docon docon-status-error-outline" aria-hidden="true"></span> Note</p>
<p>There is no MDI compatibility option in Excel.</p>
</div>
<p>In dual-monitor systems, the SDI in Excel enables side-by-side comparisons of two workbooks by dragging each workbook to a different monitor. Each workbook works independently of the other.</p>
<p>To see SDI and MDI in action, if you have both Excel 2010 and Excel 2013 available, perform the following steps.</p>
<div class="heading-wrapper" data-heading-level="h3"><a class="anchor-link docon docon-link" href="#to-contrast-the-number-of-processes-for-mdi-and-sdi-interfaces" aria-label="Section titled: To contrast the number of processes for MDI and SDI interfaces"></a><h3 id="to-contrast-the-number-of-processes-for-mdi-and-sdi-interfaces" class="heading-anchor">To contrast the number of processes for MDI and SDI interfaces</h3></div>
<ol>
<li>On the Windows Start menu, start Excel 2010.</li>
<li>Start a second occurrence of Excel. Verify that the two Excel windows are displayed.</li>
<li>On the Windows Task Bar, choose and then select <strong>Start Task Manager</strong>.</li>
<li>Choose the <strong>Processes</strong> tab and then scroll down until you see the two <strong>Excel.exe</strong> entries. This tells you that, by default, Excel opens a new instance each time it is called (two Excel instances).</li>
<li>Close the two instances of Excel.</li>
<li>On the Windows Start menu, choose Excel 2013.</li>
<li>Start a second occurrence of Excel. Verify that the two Excel windows are displayed.</li>
<li>Start the Task Manager again.</li>
<li>On the <strong>Processes</strong> tab scroll down until you see <strong>Excel.exe</strong>. Be aware that although you opened two occurrences of Excel, the two workbooks are contained in the same single instance of Excel.</li>
</ol>
<p>To see how SDI and MDI work inside of an instance of Excel, perform the following steps.</p>
<div class="heading-wrapper" data-heading-level="h3"><a class="anchor-link docon docon-link" href="#to-compare-the-number-of-excel-instances-for-mdi-and-sdi-interfaces" aria-label="Section titled: To compare the number of Excel instances for MDI and SDI interfaces"></a><h3 id="to-compare-the-number-of-excel-instances-for-mdi-and-sdi-interfaces" class="heading-anchor">To compare the number of Excel instances for MDI and SDI interfaces</h3></div>
<ol>
<li>On the Windows Start menu, choose Excel 2010.</li>
<li>Choose the Excel window to make it active and verify that <strong>Book1</strong> is the current workbook.</li>
<li>Press CTRL + N to open another workbook. Verify that <strong>Book2</strong> is now the current workbook.</li>
<li>Minimize <strong>Book2</strong> and then see Book1. Both workbooks are contained in the same instance of Excel.</li>
<li>Close Excel.</li>
<li>On the Windows Start menu, choose Excel 2013.</li>
<li>Choose the Excel window to make it active and verify that <strong>Book1</strong> is the current workbook.</li>
<li>Press CTRL + N to open another workbook. Verify that <strong>Book2</strong> is opened in a separate window (but still in the same instance of Excel).</li>
<li>Close Excel.</li>
</ol>
<div class="alert is-info">
<p class="alert-title"><span class="docon docon-status-error-outline" aria-hidden="true"></span> Note</p>
<p>You can open multiple instances of Excel by using the following command line switch: <strong>excel.exe /x</strong>. This switch starts Excel in a new process.</p>
</div>
<p>In this article, we will discuss the implementation of the SDI in the Excel UI and how it impacts programmability in Excel.</p>
<div class="heading-wrapper" data-heading-level="h2"><a class="anchor-link docon docon-link" href="#whats-changed-in-the-user-interface" aria-label="Section titled: What's changed in the User Interface"></a><h2 id="whats-changed-in-the-user-interface" class="heading-anchor">What's changed in the User Interface</h2></div>
<p>If you look closely after opening an Excel workbook, you no longer see the window state buttons ( <em>minimize</em>, <em>maximize</em>, and  <em>restore</em>) in the upper-right corner of the ribbon. Figure 3 shows the window state buttons that are available in Excel and Excel 2007. Because the top-level window is now tied directly to a single workbook or workbook view, there is no longer a need for the windows management UI in Excel.</p>
<p><strong>Figure 3. Windows state UI in Excel 2010</strong></p>
<p><img src="../../images/odc_xl15_ta_programmingthesdiinexcel2013_03.jpg" alt="Windows state UI in Excel 2010" data-linktype="relative-path"></p>
<p>Additionally, starting in Excel, there are no longer multiple workbook windows inside of a single Excel instance window such as seen in Figure 4.</p>
<p><strong>Figure 4. Multiple workbooks in a single Excel instance window</strong></p>
<p><img src="../../images/odc_xl15_ta_programmingthesdiinexcel2013_04.jpg" alt="Multiple workbooks in a single Excel instance" data-linktype="relative-path"></p>
<div class="heading-wrapper" data-heading-level="h2"><a class="anchor-link docon docon-link" href="#recalculation-and-formulas" aria-label="Section titled: Recalculation and Formulas"></a><h2 id="recalculation-and-formulas" class="heading-anchor">Recalculation and Formulas</h2></div>
<p>Recalculations in Excel will still be "global" meaning that they occur across workbooks in the same instance of Excel. Formulas that reference across workbooks that are open in the same instance of Excel will participate in calculations together and will share the same workbook calculation mode (automatic, automatic except for data tables, and manual).</p>
<p>In MDI, there is only one formula bar to handle all open workbooks in that instance of Excel. In SDI, there is one formula bar per workbook. For SDI, when editing cross-book references in a formula, both the source and target workbook formula bars will show the formula currently being edited as shown in Figure 5.</p>
<p><strong>Figure 5. Updating cross-workbook formulas</strong></p>
<p><img src="../../images/odc_xl15_ta_programmingthesdiinexcel2013_05.jpg" alt="Updating cross-workbook formulas" data-linktype="relative-path"></p>
<div class="heading-wrapper" data-heading-level="h2"><a class="anchor-link docon docon-link" href="#custom-task-panes" aria-label="Section titled: Custom Task Panes"></a><h2 id="custom-task-panes" class="heading-anchor">Custom Task Panes</h2></div>
<p>Custom Task Panes that attached to a top level window in MDI are now attached to a particular workbook's window in SDI. Switching to a different workbook will activate that workbook window, which won't necessarily have the custom task pane attached, unless the developer's code is updated to specifically display the custom task pane for that workbook.</p>
<p>To summarize, as a developer, you'll want to:</p>
<ul>
<li>Ensure that for any workbooks where you want to show the custom task pane, you write code to explicitly do that.</li>
<li>Ensure that you explicitly handle updating the custom task pane state across all instances, if you want all of the custom task panes to reflect the same state. For example, a check box is toggled to ON by the user, and you want that to be reflected across all of the custom task panes in all instances of Excel.</li>
</ul>
<div class="heading-wrapper" data-heading-level="h2"><a class="anchor-link docon docon-link" href="#custom-ribbons" aria-label="Section titled: Custom Ribbons"></a><h2 id="custom-ribbons" class="heading-anchor">Custom Ribbons</h2></div>
<p>Custom ribbon tabs and controls that assumed a single ribbon UI per application instance in previous versions of Excel will now be propagated onto each workbook ribbon in Excel. Whereas in MDI the custom ribbon developer didn't need to consider multiple instances of their controls on different instances of Excel's ribbon UI, with SDI they will need to account for this situation.</p>
<p>If you want to keep all the ribbon UI controls in the same state across open workbooks, you'll need to:</p>
<ul>
<li>Ensure that the code is able to cycle through the workbook windows and update the state of the controls.</li>
</ul>
<p>OR</p>
<ul>
<li>Cache the state of the controls so that when the user switches to another workbook, that event can be captured and the controls updated as part of the window switch.</li>
</ul>
<p>Additionally, consider the case where you develop code to add a custom UI control by using <code>Application.Commandbar</code> to access the ribbon. When you try to access that control at a later time, your code will need to account for the fact that the active workbook may not be the same workbook where you added the control.</p>
<div class="heading-wrapper" data-heading-level="h2"><a class="anchor-link docon docon-link" href="#considerations-for-vba-code" aria-label="Section titled: Considerations for VBA code"></a><h2 id="considerations-for-vba-code" class="heading-anchor">Considerations for VBA code</h2></div>
<p>With the shift to SDI, all of the Excel  <em>application-level</em> window methods, events, and properties remain unaffected and work the way they have in previous versions of Excel (for example, <code>Application.ActiveWindow</code>, <code>Application.Windows</code>, and so on).</p>
<p>In Excel, all of the <em>workbook-level</em> window methods, events, and properties now operate on the top level window (for example, the <code>Workbook.WindowActivate</code> event is still triggered when you switch to a particular workbook, the <code>Workbook.Resize</code> event is still triggered when that workbook is resized, and <code>ThisWorkbook.Windows(1).Height</code>, <code>ThisWorkbook.Windows(1).Width</code>, <code>ThisWorkbook.Windows(1).Left</code>, <code>ThisWorkbook.Windows(1).Right</code>, <code>ThisWorkbook.Windows(1).Minimize</code>, <code>ThisWorkbook.Windows(1).Maximize</code> and so forth will operate on the top level window for the active workbook).</p>

</li>
<li><p>Assume that your VBA code opens multiple workbooks and uses the <strong>DataEntryMode</strong> property to control data entry and workbook closure. In the Excel SDI model, because each workbook is contained in its own process, the <strong>DataEntryMode</strong> property used in one workbook does not recognize the existence of other workbook and therefore has little to no effect on their interaction. <div class="heading-wrapper" data-heading-level="h2"><a class="anchor-link docon docon-link" href="#summary" aria-label="Section titled: Summary"></a><h2 id="summary" class="heading-anchor">Summary</h2></div>
<p>The new Single Document Interface in Excel 2013 makes it easy to work with multiple workbooks. You can even drag the workbooks to different monitors for convenience. You just need to remember that there is only one top-level window and one ribbon UI menu per workbook. This may require that you update any existing code to cache the state of controls and settings as you move from workbook to workbook.</p>
